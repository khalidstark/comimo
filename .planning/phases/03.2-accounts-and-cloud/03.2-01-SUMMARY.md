# Phase 03.2 Plan 01: Accounts Summary

**Email + password accounts with scrypt hashes, KV-backed sessions and an account-keyed spending guard shared across instances; signed-out visitors who tap Record go to a one-screen sign-up and come straight back.**

## Performance

- **Completed:** 2026-10-31
- **Tasks:** 2 of 2
- **Commits:** 21 on branch `accounts` (pushed; not merged)

## Accomplishments

- KV adapter (`get/set/del/incr` with TTL and set-if-new): `FileKV` under `.data/` (gitignored, serialised writes, atomic rename) and `UpstashKV` (INCRBY+EXPIRE in one Lua EVAL). Upstash is used when `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` (or Vercel's `KV_REST_API_URL` + `KV_REST_API_TOKEN`) exist.
- Accounts: normalised unique email (claimed with set-if-new, so racing sign-ups can't both win), display name, scrypt N=2^15 r=8 p=1 with a 16-byte random salt, constant-time compare, dummy hash for unknown emails.
- Sessions: 32 random bytes, kept in KV only as a hash, 30-day TTL; cookie httpOnly, SameSite=Lax, path /, 30 days; `__Host-comimo_session` + Secure in production; sign-out deletes the KV record.
- Guard: limits keyed by account id, counters in KV (daily comic/image/upload caps shared by every instance). Closes **ISS-008**. The meter stays synchronous for the model code and writes each call to KV (flushed with `after()`).
- Every generation route (`transcribe`, `script`, `panel`, `character`, `character/photo`, `sprite`) answers 401 `{ error, code: "signin" }` without a session and 403 on a cross-site POST. `panel/route.ts` changed by 3 lines only (import, 2-line session check, `await guard`).
- UI: sign-in and sign-up pages (one screen each, show/hide password, field-level and general errors in plain words, comic panel art); nav shows name + avatar with a menu (My comics → /month, Sign out) or "Sign in"; proxy on /record; client re-check for stale cookies; home hero "Start your comic book" for signed-out visitors.

## Decisions Made

- No guest try-out (user decision): proxy redirects signed-out /record to sign-up with `next`.
- `next` after sign-in is limited to a fixed list (/, /record, /cast, /month, /day/<id>).
- Per-email lockout: 5 free tries an hour, then one try per lock of 1, 2, 4 ... 60 minutes. Per IP: 50 tries an hour. Without a trusted IP (dev only): a global bucket (1000/hour, short locks) with a progressive delay after 200 tries.
- Sign-ups: 5/hour and 20/day per trusted IP; global 30/hour and 150/day without one.

## Deviations from Plan

### Auto-fixed Issues (security review, during execution)

1. **Sign-in lockout TOCTOU** - tries are now reserved atomically before the password check; past the free tries only the request that creates the lock (set-if-new) gets through. Verified: 20 parallel wrong guesses give 6 × 401 and 14 × 429.
2. **Cookie tossing** - only this environment's cookie name is read (`__Host-` only in production).
3. **Shared "local" IP bucket** - per-IP limits need a trusted IP (Vercel, or `COMIMO_TRUSTED_IP_HEADER`); otherwise global buckets apply, and production refuses sign-in/up (503, one log line with no user data).
4. **Counter decrement abuse** - removed the try release completely; no decrement exists in the sign-in path.
5. **Open redirect via normalised `next`** - allowlist of in-app pages, rebuilt from the normalised pathname.
6. **Build-time prerender of /api/auth/me** - `connection()` first, so the handler never runs (or swallows Next's abort) during the build.

**Impact on plan:** all security hardening; no scope change.
