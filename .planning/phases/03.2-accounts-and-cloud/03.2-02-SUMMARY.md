# Phase 03.2 Plan 02: Cloud Comics and Photo Albums Summary

**Each account's comics, cast and images now live on the server (Vercel Blob private store + Upstash, local folders in dev) and sync both ways with a per-account IndexedDB cache; every day can carry a real photo album behind an unguessable link, printed as a QR code on the comic's last page and in the magazine.**

## Performance

- **Started:** 2026-10-31 12:20 EET
- **Completed:** 2026-10-31 13:05 EET (plus review rounds)
- **Tasks:** 2 of 2
- **Commits:** 26 on main (19 feat, 7 fix from the security reviewer), each pushed

## Accomplishments

- **Library API** (`/api/me/library`, `/days/:id`, `/cast/:id`, `/meta/:key`, `/images/:id`): every call needs a session (and same-origin for writes); the account id comes only from the session; another account's id answers 404. Last write wins by `updatedAt`, older copies get 409, stamps more than 10 minutes in the future are refused, deletions leave tombstones. Bodies bounded (day 256 KB, character 64 KB, image 8 MB, setting 16 KB).
- **Images:** magic-byte checked, stored exactly as sent at `a/<account>/i/<id>/<version>`, served `private, no-store` with `nosniff` and `CSP sandbox`. Quotas per account (2 GB, 40k images), hourly uploads per account (600) and daily for everyone (50k), all env-tunable and atomic.
- **Store/sync:** one IndexedDB per account (`comimo-<cacheKey>`, a salted hash), the device DB stays for signed-out use. Pages wait up to 8 s for the first sync; missing days and images are fetched on first view; redrawn sheets drop their cached copies. Offline edits and deletions are sent at the next sync.
- **Move comics:** signed in on a browser with pre-account comics, a card offers "Move these comics to your account"; the device database is deleted only when everything arrived.
- **Albums:** 128-bit ids; up to 20 photos (JPEG/PNG/WebP/HEIC by magic bytes, at most 5 MB, re-encoded without EXIF/GPS at most 2048 px) or a pasted https link; owner can add/remove photos, edit captions, get a new link (old id dies at once), delete. Per-account photo cap (400), hourly uploads (60) and daily global cap (3000); the album's 20 and the account's total are reserved atomically. Public page `/album/:id` in the zine style, noindex/noimageindex, `referrer: no-referrer`, only photos, captions and the day title.
- **Captions:** "Suggest captions" sends 768 px copies to Muse Spark (`/responses`, `store: false`), guard action `caption`, never automatic.
- **QR:** `qrcode` matrix drawn as one SVG path (no library HTML), URL from `NEXT_PUBLIC_SITE_URL` or the page origin; on the comic's last page and the day's last page in the magazine.
- **Account deletion** (`/account`, `DELETE /api/me/account` with password): deleting mark first (sessions refused, albums hidden), then albums, library and blob folder, sessions, record and email, mark last; finished by the owner's next sign-in attempt or `POST /api/maintenance/deletions` (Bearer `COMIMO_MAINTENANCE_SECRET`) if a step fails. Sessions are honoured only while the account record exists and isn't marked.

## Deviations from Plan

### Auto-fixed Issues (security review, during execution)

1. **Image quota race** - hget/incr was not atomic; now one atomic sized-put per account, reserved before the blob write.
2. **Accounting not bound to bytes** - same-id uploads could write one path; now versioned paths, rollback only of one's own version, stale versions deleted after commit.
3. **Free retries over quota** - refused uploads no longer refund rate slots; recount at most hourly.
4. **Deletion fail-open / ordering / revocation** - password must verify against a loaded account; deleting mark first; sessions and new sign-ins refused for missing or marked accounts; resumable cleanup.

### Other

- Mock comics draw SVG placeholders; to let mock comics sync, script-free SVG is accepted only while mock mode is on.
- The album page needs `instant = false` (unknown params with the nav's `usePathname`), and the 404 for a missing album comes from the proxy as a static page.
- Day deletion has no UI yet; the store and API support it (tombstones).
